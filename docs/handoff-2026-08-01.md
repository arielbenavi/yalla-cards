## What was learned — read this before touching content

### chatifai invents things. Four caught this session.

| fabrication | where | what it actually means |
|---|---|---|
| `לַוְזִין` / `לַקְטַה` | market dialogue | offered as "premium produce"; neither corroborated |
| `עַ-בַּלַאש` | cafe dialogue | glossed "meanwhile"; means **for free** |
| `מוחד` / `موخد` | taxi dialogue | not a word at all, in both columns |
| `מַיַّאתִי` | possessive verification | not a real inflection of مي |

**Never pass a chatifai replacement through without corroborating it.** When it
cannot be corroborated, prefer deleting the phrase over substituting — a shorter
correct sentence beats a longer invented one. This is now standing practice and
it has held up four times.

### chatifai's "polished version" silently corrupts

It routinely marks a line תקין and then rewrites it in its summary block,
dropping shaddas throughout. The worst instance: it wrote `וַקֵע` for `וַקֵّע` on
a line it had just called "תקין מאוד" — that shadda is the whole difference
between وقّع (sign) and وقع (fall), so its improvement turned "sign here" into
"fall here".

**Take the per-line verdicts. Never paste the polished block.**

Its summary counts are also unreliable — it reported ض in lines that contain no
ض three separate times, while its individual line entries were correct.

### The stored dialogues are not chatifai content

The 15 `simulation_*` rows in `paradigms` were generated by a general-purpose
model. Evidence: ض transliterated as ד׳ in **four audited dialogues out of four**,
and `شقل` for shekel appearing in zero cards but four dialogues. Both are now
fixed mechanically across all 15 by `scripts/apply-dialogue-fixes.ts`, which
applies global word corrections to every dialogue and per-line audited fixes only
to those chatifai has reviewed. `scripts/scan-dialogue-dad-errors.ts` proves zero
ض errors remain.

**The mechanical pass does not mark anything verified.** Fixing a known
transcription defect is not the same as having content reviewed.

### The ق convention is deliberately unresolved

chatifai recommends transliterating ق as א everywhere in urban Palestinian. It is
**held**, for two reasons: the four pointed forms it supplied contradict its own
rule, and "always hamza" is true for Jerusalem/Ramallah/Nablus but rural and
Bedouin speech uses k/g — a learner writing א everywhere would mis-hear them.
Cards keep `קְבַּאל`. If this is ever adopted it must move as one decision across
`וַקְת`, `קְבַּאל`, `קַדֵّיש`, `بقدر` together, never piecemeal.

Watch for chatifai referring to this as settled — it has already written "כפי
שסיכמנו" about a decision that was explicitly parked.

**The dialogues are already inconsistent about it**: `הַלְאֵית` in car_trouble and
family_chat, `הַלְקֵית` in clothes_shop; `אַדֵّיש` against `קַדֵّיש`. Also `וִאְפַת`,
`תִאְלַא`, `אִסְתִאְבַּאל`, `מִנְאֻעֻד`, `סוּא`. The cards are uniformly ק, so the
dialogues are the outliers — but normalising them is still the same one
decision and must not be done piecemeal.

**chatifai contradicts itself on ظ.** In the doctor audit it ruled ז׳ wrong and
ט׳ right, with reasoning. In the self_intro audit it marked ז׳ "correct" with
none. The cards write ט׳ and that stands. A reasoned ruling outweighs a bare
approval — and this is the second convention it has been inconsistent about.

### Data hazards that bit this session

- **Card inserts and `card_srs` inserts are separate statements.** 199 of 820
  cards had no `card_srs` row and could never appear in review, including all 82
  of מפגש בעפ 2. Same gap exists for `verb_conjugations` → `conjugation_srs`.
  Always create the SRS row and verify.
- **Seed migrations without `ON CONFLICT` get re-applied.** `0013_seed_verbs.sql`
  ran seven times. `scripts/migrate.ts` now tracks applied migrations.
- **Arabic marks hide inside Hebrew transliteration.** Arabic shadda U+0651 and
  Hebrew dagesh U+05BC render identically. 61 cards had the Arabic one. This is
  not cosmetic: `translit_normalized` strips `[֑-ׇ]`, which is Hebrew marks
  only, so U+0651 survives normalisation and dedup can never pair those cards.
  `scripts/scan-script-mixing.ts` checks cards, verbs, possessives, songs and
  dialogues. Easy to reintroduce by typing — I did it twice in one session.
- **`.in()` over ~850 ids overflows the PostgREST URL** and returns empty
  silently. Fetch small tables whole and join in memory.
- **A plain `select()` caps at 1000 rows.** `review_log` is well past that, so an
  unpaged read undercounts reviews — it reported 0 for a card with 2 and nearly
  made the duplicate merge keep the wrong side. Page every read of a big table.
- **`LIKE` against a uuid column errors** ("operator does not exist: uuid ~~
  unknown"). Fetch and prefix-match in JS.
- **Nikud normalisation differs** between Postgres and a TS source literal.
  Compare with `.normalize("NFC")` or identical-looking strings won't match.
- **`npx tsc --noEmit` is weaker than `npx next build`.** A Supabase upsert over
  differently-shaped array elements passes one and fails the other. Build before
  pushing; a pre-push hook runs it anyway.
- **Playwright reuses a running dev server.** Restart it after changing an API
  route or the tests run against stale code.

### The chatifai agent has no Bash tool

Only Chrome tools. Never send it a script to run or ask it to query the DB — dump
the rows yourself and paste the text into the message. Ask about transliteration
as an explicit numbered question; left implicit, chatifai answers only about
naturalness and silently alters vocalisation.
