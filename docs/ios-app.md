# The iPhone app

A native iOS app (Capacitor) whose main screen is the daily review, working
with or without a network. Everything else — songs, focused practice,
conversation, browse — opens from it in an in-app Safari sheet on
https://yalla-cards.vercel.app.

## How offline works

| Piece | Where |
|---|---|
| The deck + FSRS state, kept on the phone | `GET /api/mobile/deck` → `deck.json` in the app's data folder |
| The daily queue, built on the phone | `lib/daily-queue.ts` — mirrors `app/api/review/queue/route.ts` (change them together) |
| Grading on the phone | `lib/fsrs.ts` `scheduleReview`, the same function the server uses |
| Grades made offline | `pending.json`, sent to `POST /api/mobile/sync` when online |
| Card audio | downloaded once into `audio/`, plays offline |

The phone schedules locally so the queue moves on as you grade, but the server
stays the source of truth: `/api/mobile/sync` re-schedules each grade server
side with the time it was actually made, then the phone takes a fresh deck.
A grade sent twice is recognised (same card + same time in `review_log`) and a
grade older than the card's last review (it was reviewed on the web meanwhile)
is skipped rather than rewinding the schedule.

Sync runs on launch, when the app comes back to the foreground, when the
network returns, after every grade, and from the "סנכרן" button.

Check the phone's queue against the server's at any time:

```
npx tsx scripts/check-daily-queue.ts https://yalla-cards.vercel.app
```

## Files

- `mobile/src/` — the app's screens (React), storage and sync (`store.ts`)
- `mobile/build.mjs` — bundles it into `mobile/www`
- `mobile/ios/` — the Xcode project (generated by `npx cap add ios`, then edited:
  iPhone only, portrait, Hebrew, `ITSAppUsesNonExemptEncryption = NO`)
- `mobile/make-art.py` — draws the icon and launch screen
- `mobile/release.sh` — archive + upload to TestFlight
- `capacitor.config.ts` — bundle id `com.arielbenavi.yallacards`

## Developing

```
npm run dev                                            # the Next server
API_BASE=http://localhost:3000 DRY_RUN=1 node mobile/build.mjs
npx cap sync ios
open mobile/ios/App/App.xcodeproj                      # ▶ on a simulator
```

`DRY_RUN=1` makes `/api/mobile/sync` compute and write nothing, so testing never
touches the real FSRS state (the local server uses the production database).

## Releasing to TestFlight

One-time setup on Re'ut's account (she is the Apple Developer account holder):

1. **Register the bundle id** — developer.apple.com → Certificates, Identifiers &
   Profiles → Identifiers → **+** → App IDs → App → Description `Yalla`,
   Explicit Bundle ID `com.arielbenavi.yallacards` → Continue → Register.
2. **Create the app** — appstoreconnect.apple.com → Apps → **+** → New App:
   iOS, name `יאללה כרטיסים` (must be unique on the App Store — if taken,
   `Yalla Cards Arabic`), primary language Hebrew, the bundle id above,
   SKU `yallacards`.
3. **API key for uploading** — App Store Connect → Users and Access →
   Integrations → App Store Connect API → Team Keys → **+** (the first time,
   "Request Access" and accept) → name `yalla upload`, access **Admin** →
   Generate → download the `.p8` (it can be downloaded only once). Send Ariel
   the `.p8` file, the **Key ID**, and the **Issuer ID** shown above the list.
4. **Team ID** — developer.apple.com → Account → Membership details → Team ID.
5. **Add Ariel as a tester** — App Store Connect → Users and Access → **+** →
   Ariel's Apple ID email, role **App Manager**. (Users on the team are
   internal testers: builds reach them with no Apple review.)

Then, from this Mac (put the key at `mobile/AuthKey_<KEYID>.p8` — git-ignored):

```
TEAM_ID=XXXXXXXXXX ASC_KEY_ID=XXXXXXXXXX ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx ASC_KEY_PATH=mobile/AuthKey_XXXXXXXXXX.p8 mobile/release.sh
```

After Apple processes the build (5–15 min): App Store Connect → the app →
TestFlight → Internal Testing → **+** group → add Ariel → add the build. Ariel
installs **TestFlight** from the App Store on the iPhone and accepts the invite.

Every later release is just the `mobile/release.sh` line again. A TestFlight
build expires after 90 days; uploading a new one renews it.

## Without a paid account (what runs now)

`mobile/install-iphone.sh` builds with the free Apple ID signed into Xcode and
installs on the iPhone (cable or same Wi-Fi). Bundle id `il.ariel.yalla.personal`
— the App Store one is taken for a personal team. The signature lasts 7 days;
run the script again to renew. Data on the phone survives the reinstall.
First install only: iPhone → Settings → General → VPN & Device Management →
trust the developer; Developer Mode on (Privacy & Security).

## The website offline

`npm run build` also builds the same offline review into `public/app/`
(`mobile/build.mjs --web`, same-origin API). `public/sw.js` keeps it, and any
page that cannot load offline shows it instead. `components/OfflineSupport.tsx`
registers the worker and, once per online visit (at most every 30 min), loads
`/app/` in a hidden frame for a minute so the deck and audio on the device stay
fresh and offline grades get sent. Works from Safari and from the home-screen
icon (Share → Add to Home Screen).
